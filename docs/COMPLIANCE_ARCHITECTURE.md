# 直播风控规则架构

本文记录实时直播合规判断的模块边界和数据流。目标是让收音、转录和主播提示不依赖远程服务，同时让跨句隐喻、规则学习和历史复核有明确的人工控制点。

## 判断链路

```text
最终转录
  -> 当前直播间 + 当前商品 + 商品行业/类目/合规画像 + 说话人上下文
  -> 本地内置规则 / 已发布自定义规则
  -> 立即生成 safe / warning / blocked 和主播替代表达
  -> 按风险档位决定豆包语义复核
  -> 豆包结果与本地结果择高
  -> 风险证据卡展示置信度、完整原话和命中片段
  -> 中控确认后写入直播间本地规则，随后可提交服务运营审核
  -> 运营采纳后复制到公共规则库；待定/舍弃不影响本地规则
```

本地规则是第一道防线，负责词级和句级确定性判断；豆包只负责本地规则难以稳定表达的连续语义、隐喻和上下文判断。远程请求超时或失败时保留本地结果，不暂停麦克风、不结束直播。

## 商品合规画像

商品录入后生成随商品保存的合规画像，包括行业、标准类目、默认平台规则集、合规资料描述、高风险短语、语义风险边界、必要披露和安全介绍方向。默认平台规则集固定为 `douyin-ecommerce-live`，对应抖音带货直播间。

保存链路本地优先：本地分类立即写入并同步当前场次，豆包画像以低优先模型任务自动补全，直播中也会执行，但最多占用 1 个模型并发并为实时合规、主播提词预留容量。豆包结果和本地兜底均为待复核画像；只有中控人工确认或修改后，画像明确短语才成为 `blocked` 快速判断，未确认画像命中返回 `warning`。

商品事实变化会让非人工画像重新识别，人工画像不会被后台任务覆盖。后台画像到达时，编辑界面只合并行业、标准类目和画像字段，不覆盖用户正在编辑的名称、描述、卖点或价格。

实时语义请求携带平台规则集、行业、标准类目、合规摘要、风险边界和必要披露。风险边界中的疾病治疗、绝对效果、排名、资质、检测、性能等概念会触发提前语义复核；通用广告法与抖音直播红线始终执行，画像只能增加商品特有边界，不能降低内置规则风险。

## 上下文边界

- 上下文在商品切换时重新开始，最多保留最近 12 条主播最终转录。
- 时间窗口为 30 秒，过期内容不回填到新的商品判断。
- `speaker=other` 的内容不会进入主播话术语义上下文，但仍保留在场次记录中，供人工复盘和说话人纠错。
- 规则命中使用当前直播间的商品资料快照，历史场次不会被后续改价或改文案污染。

## 规则作用域

规则只在所属直播间内读取，按以下优先级选择：

1. 商品级：只对 `productId` 匹配的商品生效。
2. 品类级：对当前商品 `category` 匹配的商品生效。
3. 直播间级：对该直播间所有商品生效。

同一段话命中多条规则时，风险等级优先，其次是作用域、匹配长度和版本号。内置高风险规则不能被自定义规则降级。

主播提词使用“原话优先、商品资料约束”的顺序：主播最终转录先触发商品提及匹配，主播明确说出其他商品时先自动切换当前商品，再以这句原话作为豆包和本地预测的首要输入。商品资料只用于事实核验和没有足够原话时的安全兜底，不会替代主播当前话题。

## 生命周期

```text
learned / pending_review
          | 中控批准
          v
       published <---- rollback（生成新版本）
          |
       disabled / rejected
```

豆包高置信 `term` 发现只会生成 `pending_review` 且 `enabled=false` 的规则。中控批准后才进入本地快速路径；驳回、停用、批准和回滚都写入 `rule_audits`。规则版本写入 `rule_versions`，资源交付任务使用 `ruleId:version` 幂等，旧任务会标记为 `superseded`。

## 风险档位

| 档位 | 豆包调用策略 | 建议 |
| --- | --- | --- |
| 严格 | 每句复核；隐喻和高风险提醒立即复核 | 新主播、高风险商品、试播 |
| 均衡 | 普通安全表达每 4 句抽样；敏感表达立即复核 | 默认 |
| 优化 | 普通安全表达每 8 句抽样；敏感表达立即复核 | 成熟主播、稳定商品 |

食品、保健、医疗、护肤等高风险行业在均衡档位每 2 句抽样、优化档位每 4 句抽样；严格档位仍逐句复核。

采样键包含 `roomId + productId + speakerId`，换商品、换直播间或换说话人都会重新计数。安全表达的抽样不影响本地规则逐句执行。

## 人工复核入口

- `POST /api/v2/rules/:ruleId/review`：批准或驳回待审核规则。
- `POST /api/v2/rules/:ruleId/rollback`：指定历史版本生成新的当前版本。
- `GET /api/v2/rooms/:roomId/rules`：查看规则、状态和审计记录。

规则治理和场次复核是两条独立流程：场次转录修改必须人工批准后上传；中控确认的规则只写入当前直播间并立即生效，之后通过 `public-submit` 进入服务运营队列。运营审核台可选择采纳、待定或舍弃，只有采纳才创建 `public-library` 公共规则；待定和舍弃不会删除或停用原直播间规则。规则证据同时保存完整原话、命中片段、置信度、证据次数和最后一次 finding ID，重复确认同一 finding 幂等。

公共审核入口：`GET /api/v2/operations/rules`、`POST /api/v2/rules/:ruleId/public-review`，仅 `reviewer` 身份可用；商家中控只使用 `POST /api/v2/rooms/:roomId/rules/confirm` 和 `POST /api/v2/rules/:ruleId/public-submit`。
